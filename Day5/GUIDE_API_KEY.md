# Гайд для коллеги: Настройка API ключа a101.ru (ai-public)

Привет! Чтобы наше Web-приложение (и инструменты вроде OpenCode) могли обращаться к нейросетям через корпоративный шлюз a101.ru, тебе нужно прописать свой личный API-ключ в систему.

Ниже описаны два способа это сделать. Используй тот, который тебе удобнее.

---

## Способ 1. Сохранение ключа в файл (Рекомендуемый для OpenCode)

Система (и конфигурация `opencode.jsonc`) по умолчанию ищет ключ в специальном скрытом файле. 

1. Открой командную строку (PowerShell или CMD) на своем компьютере.
2. Создай скрытую папку `.secrets` в своей домашней директории, если её еще нет:
   ```powershell
   mkdir $env:USERPROFILE\.secrets
   ```
3. Запиши свой API-ключ в файл `ai-public` внутри этой папки. Замени `ТВОЙ_API_КЛЮЧ` на реальный ключ, который тебе выдали:
   ```powershell
   "ТВОЙ_API_КЛЮЧ" > $env:USERPROFILE\.secrets\ai-public
   ```
   *(Пример: `"sk-or-v1-abcdef123456..." > C:\Users\ИмяПользователя\.secrets\ai-public`)*

**Проверка:** Теперь инструменты, использующие конфигурацию `opencode.jsonc`, автоматически найдут твой ключ.

---

## Способ 2. Ввод ключа напрямую в Web UI

Если ты просто хочешь запустить наши Web-приложения для тестов (День 2, День 3, День 4, День 5) без настройки системных файлов:

1. Запусти сервер приложения через Python:
   ```bash
   python app.py
   ```
2. Открой в браузере `http://localhost:5000`
3. В самом верху интерфейса ты увидишь поле **"API Key (a101.ru)"** или **"Корпоративный Ключ"**.
4. Просто скопируй свой ключ туда. Приложение будет использовать его для всех запросов в текущей сессии (до обновления страницы).

---

### Важное примечание про модели
Мы используем корпоративный прокси (`https://ai-public.a101.ru/api`), поэтому в коде мы должны указывать названия моделей **строго так, как они прописаны в конфиге**. 
Например: `openai/gpt-5.6-luna`, `openrouter/claude-sonnet-5`. Если использовать стандартные имена (например, `gpt-4o`), прокси выдаст ошибку `400 Bad Request`.
